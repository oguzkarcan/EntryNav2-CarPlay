# EntryNav2 / EVO Vehicle Facts Ledger (Phase 4 & Platform Audit)

Audit baseline: **`EntryNav2-Android-Auto` `v0.12.0` -> `v0.13.0-rc.6`**, **`DiPlay-main`**, and the **HU_ENTRYNAV2 sysroot** (`$SYSROOT`).

This ledger tracks every vehicle-specific constant, ABI assumption, path, D-Bus coordinate, vMOST function ID, and hardware quirk used in `EntryNav2-CarPlay`, its provenance, verification status, dependent code, and live-car probe method. For how `CarPlayDaemon` and `CarPlayConnectivity` gate ALPS compatibility, toggle per-transport Wi-Fi QoS, and drive read-only link logging, see [docs/CONNECTIVITY.md](CONNECTIVITY.md). For live-car probing (`car_visit.sh` / `--compat`), QEMU sysroot runtime verification, and MFi I2C research, see [docs/CAR_VISIT.md](CAR_VISIT.md), [docs/CARLIB_SMOKE.md](CARLIB_SMOKE.md), and [docs/MFI_AUTH.md](MFI_AUTH.md).

Status legend:
- **Confirmed on target HU (verified 2026-11-21 visit 1 / visit 2):** Directly observed in read-only probe outputs (`car_visit.sh`, `carplayd --compat`, `native_carplay_probe.sh --watch`) on the target 2017 BMW F20 `HU_ENTRYNAV2` (`/etc/version` `202402191339`).
- **Confirmed in car (upstream):** Verified working on live HU_ENTRYNAV2 / NBT Evo vehicles in `EntryNav2-Android-Auto` (`v0.12.0`–`v0.13.0-rc.6`) or its referenced system binaries.
- **Confirmed on car system (upstream/sysroot):** Extracted directly from BMW head-unit binaries/configs (`libvmostclient`, `libevo_btappl`, `libAppFramework`, `libNmeCarPlay`, `wland`, sysroot).
- **Verified in DiPlay:** Confirmed against the reference `DiPlay-main` CarPlay stack.
- **Unverified (needs car):** Inferred or unexercised on a real vehicle/iPhone; must be validated during live head-unit testing.

> **Visit 1 & Visit 2 Snapshots (verified 2026-11-21 visit 1 / visit 2):** Read-only `car_visit.sh` + `--native --watch` + `carplayd --compat` runs on `Linux xse-j6-apn-entryevo 3.12.25-FR21.0` (`/etc/version` `202402191339`). Native CarPlay FSC coding fails on this unit, so `/usr/local/bin/CARPLAY` (`CARPLAY.service`, `carplay`, `Uid 1081`) stays idle (`00:00:00` CPU, no `/dev/i2c-0`, no `usbfs`, no `mdnsd` fds, empty `/var/local/data/CarPlay`, while `ExecStartPre`/`ExecStartPost` set `omapdrm` `authenticated_uid=1081` and add `wlan0` `iptables` rules). Meanwhile `DDPServer` (`DistributedDeviceProtocol.service`, `auxmms:mplayer`) permanently holds `/dev/i2c-0` open (`fd 38` in Visit 2), links `libNmeAppleAuth.so`/`libNmeAppleAuthImpl.so`, runs `NmeIAP2Link` / `NmeIAPDBusEntryEvoAudio` over ALPS **Slot 0** even with USB unplugged, and exposes no usable MFi IPC. `/etc/wayland/compositor.conf` (`995` B, `genivi-flip-renderorder = 1`) was confirmed in Visit 2. See [docs/COEXISTENCE.md](COEXISTENCE.md) for coexistence strategy and Visit 3 test items.
